## 0. この手順の意図

**作った本人が確認手順も作ると、自分が通ることを知っている道しか通らない。**
そのため、この手順は実装した側とは別に作った。

**実際のデモの流れどおりに、まっさらな状態から一周する。**
個々のAPIが動くことは各ステップで確認済み。ここで見るのは**つながり**。

### 1-b. シードデータの埋め込みを作る（必須）

**`npm run setup` の直後は `card_embedding` が空。**
シードの20件は `POST` で作られたカードではないので、
**カード登録時の自動生成（reindexCard）が走らない。**放っておくと永久に空のまま。

```bash
curl -X POST http://127.0.0.1:8787/api/search/reindex
curl -s  http://127.0.0.1:8787/api/search/status
# → embedded が total と同じ数になること
```

**これをやらないと、あいまい検索（段3）でシードのカードが1件も出ない。**
「涼しげ」「静かな雰囲気のもの」といったデモの見せ場が丸ごと消える。

本番では `REINDEX_TOKEN` を設定しているので、ヘッダが要る。

```bash
curl -X POST -H "x-reindex-token: <値>" https://<本番>/api/search/reindex
```

**デプロイした直後にも必ず実行すること。**リモートDBも同じく空から始まる。

## 2. 職人としてカードを作る（デモの前半）

| # | やること | 期待 |
|---|---|---|
| 2-1 | 職人アカウントで signup（12文字以上のパスワード） | 200、Cookie が返る |
| 2-2 | logout して login し直す | 200 |
| 2-3 | 5問に薄く答えて compose | **具体的な掘り下げ質問**が返る |
| 2-4 | 掘り下げに答えて再送 | **3文＋英訳**が返る。`ai:true` |
| 2-5 | 郵便番号で住所を引く | 都道府県・市区町村が返る |
| 2-6 | 画像を1枚アップロード | `{ key }` が返る |
| 2-7 | カードを登録（description・image_keys・lat/lng つき） | `{ ok:true, id }` |
| 2-8 | `GET /mine` | いま作ったカードが並ぶ |

**2-3 で「もう少し詳しく」のような一般的な質問が返ったら、そこで止めて報告する。**
これが返るということは、Gemini が落ちてフォールバックしている。

## 3. 一般ユーザーとして見つける（デモの後半）

| # | やること | 期待 |
|---|---|---|
| 3-1 | **ログアウトした状態**で `/api/introduce/user/next` | 200。カードが1枚返る |
| 3-2 | 同じく `/api/introduce/user/:id` | 200。画像・タグ・is_dummy が入っている |
| 3-3 | `GET /api/introduce/image/:key` | 画像が返る。content-type が正しい |
| 3-4 | いま作ったカードの言葉で `/api/search?q=...` | **段1か段3で見つかる** |
| 3-5 | 説明文の内容だけで探せる言葉で検索 | **`stage: vector` で見つかる** |
| 3-6 | 一般ユーザーで signup → いいね | `{ liked:true, like_count:1 }` |
| 3-7 | もう一度いいね | `{ liked:false, like_count:0 }` |
| 3-8 | `GET /api/introduce/user/liked` | いいねしたものだけが並ぶ |

**3-1 が 401 になったら、認証範囲が壊れている。**
未ログインでカードが見られないと、このアプリは成立しない（設計書4-3）。

**3-5 が0件なら、埋め込みが作られていない。**`GET /api/search/status` で
`embedded` の数を確認する。

## 5. 発表の直前にやること（9/5 当日）

**5分で終わる。必ずやる。**

```bash
# 1. Gemini が生きているか。モデルのエイリアスが変わっていないか
curl -sb j.txt -X POST localhost:8787/api/introduce/artisan/compose \
  --data-binary @sample.json -H 'content-type: application/json'
# → ai:true が返ること。ai:false ならモデル名かキーを確認
```

```bash
# 2. 段3が生きているか
curl -s localhost:8787/api/search/status
# → embedded が total と同じ数であること
# → 足りなければ reindex を叩く（1-b 参照）。叩かないと段3が0件になる
```

```bash
# 3. サーバーが1つだけか
netstat -ano | grep ":8787 " | grep LISTENING
# → 1行だけ。2行あると古いほうが応答する
```

**モデルは `-latest` エイリアスなので、中身が勝手に変わる。**
前日動いていても当日動く保証はない。**必ず当日に1回叩く。**
