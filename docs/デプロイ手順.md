# デプロイ手順

**2026-09-03 作成。初回デプロイ用。**

---

## 0. 先に知っておくこと

**この手順には、間違えると本番データが消える箇所があります。**
上から順に、飛ばさずにやってください。

Worker 名は **`noren`** です（プロダクト名の投票による）。
デプロイすると URL はこうなります。

```
https://noren.<アカウントのサブドメイン>.workers.dev
```

---

## 1. 事前準備

### 1-1. D1 を作る

```bash
npx wrangler d1 create teame
```

出てきた `database_id` を `wrangler.jsonc` に書きます。

> ### 【最重要】2行とも書き換えてください
>
> ```jsonc
> { "binding": "DB",                   "database_id": "<ここ>" },
> { "binding": "teame_taka_introduce", "database_id": "<ここも>" }
> ```
>
> **片方だけ書き換えると、紹介機能と検索機能が別々のDBを見ます。**
> このときエラーは一切出ません。**検索結果が常に0件になるだけ**なので、
> 原因に辿り着けません。

### 1-2. KV を作る

```bash
npx wrangler kv namespace create teame_images
```

出てきた `id` を `wrangler.jsonc` の `kv_namespaces` に書きます。

### 1-3. トークンの権限を確認する

```bash
npx wrangler whoami
```

**`d1` の権限が一覧に無いと、次の `d1 create` が権限エラーで失敗します。**
そのときは `npx wrangler login` をやり直してください。新しい権限を含めて取り直せます。

---

**シークレット（`REINDEX_TOKEN` / `GEMINI_API_KEY`）は、この段階では入れません。**
`wrangler secret put` は **Worker が存在しないと失敗する**ので、
デプロイの後（4-b）に回します。

---

## 2. スキーマを作る

```bash
npx wrangler d1 migrations apply teame --remote
```

これで次が作られます。

```
cards / card_embedding / synonym
users / sessions / likes / card_i18n / card_geo / card_images
シノニム辞書78語（段2に必須）
```

**`seeds/local_seed.sql` を `--remote` で流さないでください。**

```sql
delete from synonym;
delete from card_embedding;
delete from cards;      ← 先頭にこれが入っている
```

**本番に流すと、そのときあるカードが全部消えます。**
いまは空なので実害はありませんが、**2回目で事故ります。**

---

## 3. デモ用カードを入れる（任意）

```bash
npx wrangler d1 execute teame --remote --file=seeds/demo_cards.sql
```

`delete` を含まない版です。**入れるかどうかは判断してください。**
入れなくてもアプリは動きます（カードが0件なだけ）。

---

## 4. デプロイする

```bash
npx wrangler deploy
```

## 4-b. シークレットを入れる

**Worker ができてから入れます。**（先に入れようとすると Worker が無くて失敗します）

```bash
npx wrangler secret put REINDEX_TOKEN
npx wrangler secret put GEMINI_API_KEY
```

対話で値の入力を求められます。**再デプロイは不要**で、すぐ反映されます。

**`REINDEX_TOKEN` を入れないと、`POST /api/search/reindex` を誰でも叩けます。**
Workers AI の無料枠を空にされる可能性があります。**必ず入れてください。**
値は自分で決めた長いランダム文字列で構いません。**5番で使うので控えておくこと。**

`GEMINI_API_KEY` が無いと、カード作成が `ai:false` になり
「5問の答えを連結しただけ」の文章になります。

**値をこの手順書やコミットに書かないこと。**`secret put` は対話で入力します。

---

## 5. 【必須】埋め込みを作る

**これをやらないと、あいまい検索（段3）が1件も返しません。**

```bash
curl -X POST -H "x-reindex-token: <1-3で入れた値>" \
  https://noren.<サブドメイン>.workers.dev/api/search/reindex

curl -s https://noren.<サブドメイン>.workers.dev/api/search/status
# → embedded が total と同じ数になること
```

**カードを後から足したときも、自動で1件だけ作られます。**
ただし**シードのカードは自動生成の経路に乗らない**ので、ここで一度やる必要があります。

---

## 6. 動作確認

```bash
B=https://noren.<サブドメイン>.workers.dev

curl -s -o /dev/null -w "%{http_code}\n" $B/                 # 200
curl -s "$B/api/search?q=漆"                                  # keyword で返る
curl -s "$B/api/search?q=涼しげ"                              # synonym で返る（辞書が入った確認）
curl -s "$B/api/search?q=静かな雰囲気のもの"                   # vector で返る（埋め込みの確認）
curl -s "$B/api/introduce/user/next"                          # 未ログインで200
curl -s -o /dev/null -w "%{http_code}\n" $B/api/auth/me       # 401
```

**「涼しげ」が0件なら、シノニム辞書が入っていません。**
**「静かな雰囲気のもの」が0件なら、5番の reindex をやっていません。**

カード作成まで確認するなら、職人アカウントを作って `/dev/introduce` を開いてください。
