## 設計で守っていること

**検索のたびに外部APIを叩かない。** これが設計の芯です。

```
段1 キーワード一致    D1のみ        0円
段2 シノニム展開      D1のみ        0円
段3 ベクトル類似      Workers AI    無料枠
```

AIを使うのは**登録時に1回だけ**（埋め込み生成）。検索が何回走ってもコストは増えません。
**この方針を崩す変更（検索のたびにLLMを呼ぶ等）はしないでください。**

## 未解決の課題

- **段3のしきい値** — いま `0.45`（`search.js` の `VECTOR_THRESHOLD`）。
  実データでスコアが 0.45〜0.50 に密集したので、**絶対値ではなく相対順位で切るほうが
  安定する可能性がある**。未検証
- **説明文の質に依存する** — 段3は `description` の意味で判定するので、
  どのカードも似た文章だとベクトルが固まって区別できなくなる。
  これは検索側では直せず、**登録時にどう引き出すかの問題**

## この機能に固有の注意

- **D1 のバインディング名。**紹介機能は `teame_taka_introduce`、こちらは `DB`。
  `wrangler.jsonc` で**同じ `database_id` を2つの名前で公開**して解決しています。
  コード側で `??` で受けるのはやめました（どちらに繋がったか分からなくなるため）。
  リモートDBを作るときは**両方の行の `database_id` を書き換えること。**
  片方だけだとDBが分裂し、エラーなしで検索結果が常に0件になります
- **地図は OpenStreetMap。**Google Maps API は使いません（チーム方針）
- **`POST /api/search/reindex` は `REINDEX_TOKEN` が未設定だと誰でも叩けます。**
  ローカルを止めないための作りなので、**デプロイ時に設定するのを忘れないこと**
  （`npx wrangler secret put REINDEX_TOKEN`）
- **reindex を Cron Trigger にする案は保留中。**デプロイ先が決まっていないので入れていません
  （Cron はデプロイ済み Worker でしか動かない）。詳細は README の未決事項
